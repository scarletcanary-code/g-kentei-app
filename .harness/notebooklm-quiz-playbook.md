# NotebookLM クイズ生成 Playbook

このドキュメントは、G検定学習アプリ向けの新規問題を NotebookLM から生成し、`src/data/questions/` に取り込むまでの標準手順を定義する。

---

## 1. NotebookLM 問い合わせテンプレート

### 素材依頼プロンプト（汎用テンプレート）

```
G検定シラバス「{{CHAPTER_NAME}}」の「{{SECTION}}」の範囲で、
難易度{{DIFFICULTY}}（1=基礎/2=標準/3=応用）の4択問題を{{COUNT}}問分の素材を教えてください。

各問題の素材として以下を含めてください：
- 問題の核となる事実・定義・数値
- 正解となる情報
- 誤答候補として使えるもっともらしい誤り（同カテゴリ内で混同されやすい概念・数値）
- 出典箇所（章番号・節番号を含む形式、例: 第1章 §1.2 ○○）
```

プレースホルダー説明:
- `{{CHAPTER_NAME}}` : 章名（例: `AIとは`、`機械学習の基礎`）
- `{{SECTION}}` : 節名（例: `強いAIと弱いAI`、`チューリングテスト`）
- `{{DIFFICULTY}}` : 難易度（`1`/`2`/`3`）
- `{{COUNT}}` : 生成する問題素材数（例: `3`）

### 素材依頼クエリ例

**クエリ 1（ch1-036 用 — 強いAI vs 弱いAIの違い）**

```
G検定シラバス第1章「AIとは」の範囲で、「強いAI（汎用AI）」と「弱いAI（特化型AI）」の違いについて、
受験者が混同しやすいポイントと、それを判定できる4択問題に使える事実を教えてください。
出典箇所（章・節番号）も合わせて示してください。
```

**クエリ 2（ch1-037 用 — チューリングテスト）**

```
G検定シラバス第1章の範囲で、「チューリングテスト」の目的・提案者・評価方法について、
4択問題に使える正確な情報と誤答候補（もっともらしい誤り）を教えてください。
出典箇所（章・節番号）も合わせて示してください。
```

## 2. 問題 JSON 組み立て手順

NotebookLM の返答を受け取ったら、以下の 4 ステップで JSON を組み立てる。

### ステップ 1: 事実の抽出と問題文の確定

NotebookLM の返答から「問題の核となる事実」を 1 つに絞り込む。
問題文は「～として正しいものはどれか」「～の説明として最も適切なものはどれか」などの形式で書く。
1 問に複数の事実を詰め込まない（1問1事実の原則）。

### ステップ 2: 正解選択肢の作成

NotebookLM が示した正解情報を選択肢の文章に変換する。
正解選択肢はあいまいな表現を避け、具体的・断定的な文章にする。

### ステップ 3: 誤答選択肢 3 つの生成

誤答生成の指針:
- **同カテゴリ内で混同されやすい概念を選ぶ**: 例) 強いAI の問題なら弱いAI・特化型AI・汎用型AIを誤答候補にする
- **数値の誤り**: シンギュラリティの年（2045年）に対して「2030年」「2100年」を誤答候補にする
- **提唱者の取り違え**: チューリング・サール・マッカーシー・ミンスキーなど同時代の人物を使う
- **もっともらしい誤り**: 文章の長さや語調が正解と揃っていること。正解だけ明らかに長い・短い問題は避ける

### ステップ 4: `correctIndex` と `source_ref` の設定

**`correctIndex` の決め方**:
1. `src/data/questions/chN.json` を開き、既存問題の `correctIndex` の分布を確認する
2. `node scripts/validate-questions.mjs` を実行し、V6（分布偏り）の状況を把握する
3. 同じ章で最も少ない値（0〜3）を選ぶ
4. 選択肢の順番を入れ替えて、その値で正解が来るように調整する

**`source_ref` の書き方**:
- NotebookLM の返答中に出典が明示された場合は、その文言を **そのまま転記** する
- 例: `"JDLA公式シラバス 第1章 §1.3 AIの分類"`
- **5 文字以上** であることを確認する（`validate-questions.mjs` の V5 チェックが通ること）
- ソース名（JDLA公式・Study-AI・AVILEN・G検定の森等）と章節番号を必ず含める

## 3. 取り込み前チェック項目（スクリプト実行手順）

### 実行手順

`g-kentei-app/` ディレクトリを作業ディレクトリとして、以下のコマンドを実行する。

```bash
# ステップ A: 作業ディレクトリを確認
cd g-kentei-app

# ステップ B: 検証スクリプトを実行
node scripts/validate-questions.mjs

# ステップ C: 終了コードを確認
echo "exit code: $?"
```

**exit 0 になるまで取り込まない**。exit 1 が返った場合は、stderr に出力されたエラーを修正してから再実行する。

### 各エラーメッセージの読み方

| エラー形式 | 意味 | 対処法 |
|---|---|---|
| `[FAIL V1] 重複id: ch1-001 (ch1.json, ch3.json)` | `ch1-001` という id が複数のファイルに存在する | 新しい問題の id を `chN-XXX` の形式で一意に割り当てる |
| `[FAIL V2] ch1-005: choices が 3 件` | 選択肢が 4 つでない | 選択肢をちょうど 4 つにする |
| `[FAIL V3] ch2-010: correctIndex=5` | `correctIndex` が 0〜3 の範囲外 | 0・1・2・3 のいずれかに修正する |
| `[FAIL V4] ch3-007: explanation が 22 文字` | 解説が 40 文字未満 | 解説を 40 文字以上に書き直す |
| `[FAIL V5] ch4-003: source_ref が未定義または短すぎる` | `source_ref` がない or 5 文字未満 | NotebookLM の出典表記を転記する |
| `[FAIL V6] ch1: correctIndex=1 が 65% (23/35問) → 制限: 50%未満` | その値が全問題の 50% 超 | 追加問題の `correctIndex` を別の値にする（分布を分散させる） |

### テンプレートを使った新規問題の雛形生成

```bash
node scripts/generate-question-template.mjs
```

出力された JSON 雛形をコピーし、NotebookLM の返答内容で各フィールドを埋める。
